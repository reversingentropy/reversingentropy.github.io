The Problem

$540,000 a year in metadata. Or less.

NLB's Singapore Web Archive preserves 320,543 versions of 98,708 unique websites - digital heritage covering Singaporean life, culture, history, organisations, and events. Each archived website needs three metadata fields: a title, an abstract, and SingHeritage subject labels (NLB's local controlled vocabulary). Every field costs cataloguer time.

The GPT-4o API cost on 112 WARC files without any data reduction: $11,651.88 SGD. With heuristics applied: $7.22-$8.83 SGD. Same files, same model, different input selection. The cost problem was solved entirely in preprocessing.

The question wasn't whether LLMs could help - it was whether they could help cheaply enough to be worth it, and accurately enough to trust. A WARC file contains the full archived web content of a site: HTML, images, layout, every page crawled. Feeding a whole WARC file to GPT-4o isn't just expensive, it's wasteful. Most of the content is irrelevant to metadata generation.

The key insight

Cataloguers don't read every page of a website to write metadata. They go to the about page or the homepage. If the model only needs what the cataloguer uses, the token problem mostly solves itself.

The Approach

Data reduction first, model second

Before writing a single prompt, the team built a WARC processing pipeline: parse the archive, extract HTML responses, deduplicate on normalised URLs, filter low-quality content. This converts a raw WARC file into a structured DataFrame of page titles and text. The expensive part isn't writing - it's deciding what to send.

Three competing heuristics were developed and tested for selecting the most relevant page content from each archived site before sending anything to the model.

Heuristic 1 - selected
"About" page or shortest URL + homepage
Prioritises the about page if present (where organisations describe themselves), falling back to the shortest URL by length plus the root domain. Grounded in how cataloguers actually navigate sites.
Heuristic 2
Shortest URL + homepage
Shortest URL by length plus the website's root URL. Simpler than H1, no about-page detection logic.
Heuristic 3
Shortest URL + regex rules
Heuristic 2 plus regular expression filtering rules for additional noise removal. More complex, marginal gain.

All three heuristics were evaluated against cost and output quality using a ranked aggregation of BERTScore (maximum median), Levenshtein distance (minimum median), and standard deviation (minimum). The two best performers - Heuristic 2 with cataloguer rules and Heuristic 3 without rules - were shortlisted for manual evaluation. Heuristic 1 (the about-page approach) did not rank top in automated scoring, though it was the most behaviourally motivated.

Heuristic content selection

Apply Heuristic 1: identify the about page or shortest URL plus homepage. This reduces the content sent to the model from an entire crawled site to 1-2 pages - the ones a cataloguer would actually read. Token reduction: 99.9%. The cost problem is solved here, not at the model level.

03
GPT-4o title and abstract generation

Four prompt variants were developed and benchmarked - two without cataloguer rules (zero-shot, chain-of-thought), two with cataloguer rules embedded (templates for company sites, property sites, personal blogs). Evaluated using Levenshtein distance for title accuracy and BERTScore for abstract semantic similarity. Selected the prompt with maximum median BERTScore, minimum median Levenshtein, and minimum standard deviation across the test set.

04
SingHeritage subject label assignment

Beyond title and abstract, each website needs subject labels from NLB's SingHeritage vocabulary - 1,148 labels across 8 hierarchical levels. Three approaches were benchmarked: GPT-4o direct assignment (weighted F1: 56%), CatBoost with GTE-large embeddings (superior precision), and a Graph Neural Network over the SingHeritage label hierarchy (level 1 F1: 65%). Natural Language Inference was used as a post-processing step to filter GPT-4o hallucinations - improved precision from 0.47 to 0.51 while catching false label assignments.

Evaluation

A Turing test with eight cataloguers

The standard evaluation metrics tell you about surface similarity. They don't tell you whether a practising cataloguer would trust the output. So a blind evaluation was run using Cochran's Q test: 8 trained cataloguers assessed titles and abstracts from three sources - two GPT-4o variants and one human-curated set - without knowing which was which. Each was rated pass or fail against cataloguing standards.

The pass rates were stark: Heuristic 2 (with rules): 77.78%, Heuristic 3 (without rules): 78.70%, Human: 90.74%. Cochran's Q test rejected the null hypothesis at p = 0.02 - the difference is statistically significant. The GPT-4o outputs were distinguishable from human-written metadata. Notably, adding cataloguer rules to the prompt made almost no difference to pass rate, suggesting the bottleneck is the model's output quality, not prompt design.

The failure mode breakdown was specific: 19.6% of LLM outputs had content issues - inaccuracies, incompleteness, or hallucinations - compared to 6.3% for human-curated metadata. Language translation issues affected both equally. The pipeline ran on a Lenovo ThinkPad T14 (i5, 16GB RAM) - four hours total to process 112 files and generate metadata.

Honest finding

The quality bar for human cataloguers was not met. The paper says this plainly. The case for the system isn't that it's as good as a cataloguer - it's that 80% quality at 0.1% cost may be the right tradeoff for a collection of this scale, where the alternative is no metadata at all for most of it.

Honest reflection

What the paper says and what I'd add

The paper is honest about the limitations and so is this. GPT-4o's non-reproducibility is a genuine operational problem for a library system - metadata that changes depending on what day you run it isn't metadata you can trust. The multilingual hallucination issue wasn't fully solved. Prompting for English output doesn't guarantee English output on Chinese or Malay sites.

The SingHeritage subject label assignment work - benchmarking GPT-4o, CatBoost with GTE-large embeddings, and a GNN over the label hierarchy - was a separate workstream not covered in this paper. The GNN approach in particular (level 1 F1: 65%) was the most technically novel piece and deserves its own writeup eventually.

The broader lesson: LLMs are good at drafting, not at being right. Using them to generate a first pass that a cataloguer reviews is probably the right workflow. Using them to replace cataloguers entirely introduces quality and reproducibility problems that aren't worth the saving at the top end of the collection. At the long tail - tens of thousands of low-traffic archived sites that would never get manual metadata - the tradeoff looks much better.
